# iOS API verification (ios/ vs Apple docs)

Checked 2026-09-26 against Apple DocC JSON (`developer.apple.com/tutorials/data/documentation/<path>.json`, iOS 27 SDK docs), Apple's WWDC25 sample *Bringing advanced speech-to-text capabilities to your app* (`SwiftTranscriptionSampleApp`), and shipping code in KeyVox and hex-iphone. No Mac here, so nothing was compiled against the iOS SDK.

## TL;DR

- Every Apple symbol in `ios/` exists with the names, labels, `async`/`throws` and availability the code uses, on iOS 26.0. No iOS 27-only API is used.
- **No code edits were needed.** All 8 Swift files pass `swiftc -parse` (Swift 6.2, Docker). Type-checking against the iOS SDK still needs a Mac.
- `SpeechAnalyzer` / `SpeechTranscriber` need **no** `SFSpeechRecognizer` authorization. Apple's sample has no speech-recognition key. Our `NSSpeechRecognitionUsageDescription` is harmless, so it stays.
- Locale reservation is automatic inside `assetInstallationRequest(supporting:)`. No `reserve`/`allocate` call is needed.
- A `LiveActivityIntent` runs in the **app's** process even when a widget or control triggers it. So the widget's `#if WIDGET_EXTENSION` stub never runs for real.
- Open questions: (1) does the iOS 27 background Neural Engine rule hit `SpeechTranscriber`? (2) does the background start via `AudioRecordingIntent` work? Both need a device test. See *Unverified*.

## Semantics checked

- **Speech permission.** Apple: "This process only applies to speech recognition using `SFSpeechRecognizer`. `SpeechAnalyzer` transcriber modules don't send audio data of the user's voice to Apple's servers" ([doc](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition)). The WWDC25 sample only sets `NSMicrophoneUsageDescription` and never calls `SFSpeechRecognizer.requestAuthorization`. Only mic permission is needed.
- **Where intents run.** "If the intent conforms to … `LiveActivityIntent` … the system performs the app intent in the app's process" ([doc](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)). This covers island, Lock Screen, and control taps. The widget copy of the intent exists only so the widget compiles.
- **Audio conversion.** One `AVAudioConverter` per session, fed one tap buffer per `convert` call. The block returns `.haveData` once, then `.noDataNow`. This matches Apple's sample `BufferConverter`. The sample also sets `converter.primeMethod = .none` "to avoid any timestamp drift". We don't use timestamps, so that was left out.
- **iOS 27 has a new helper, `AnalyzerInputConverter`.** It does this conversion for you, but it is iOS 27-only ([doc](https://developer.apple.com/documentation/speech/analyzerinputconverter)). `CaptureInputSequenceProvider` is also iOS 27-only. Neither can be used at a 26.0 target without `#available`.
- **Background Neural Engine (iOS 27).** The entitlement doc scopes the rule to "inference with Core AI, Core ML, or Metal Performance Shaders Graph" ([doc](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.background-tasks.continued-processing.inference)). The release note sits under *Core AI* ([notes](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-27-release-notes)). WWDC25 session 277 says the SpeechTranscriber model "operates outside of your application's memory space" ([video](https://developer.apple.com/videos/play/wwdc2025/277/)). Foundation Models also runs out of process. So the entitlement is **probably not needed** (unverified). If background transcription fails on iOS 27, adding it is a one-line fix.
- **XcodeGen `info:`.** XcodeGen auto-generates `CFBundleIdentifier`, `CFBundleExecutable`, `CFBundleName`, `CFBundlePackageType`, the version keys, etc. ([ProjectSpec](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md#target)). It also keeps the generated `Info.plist` out of the build phases (`PBXProjGenerator.swift`, the `sourceFileBuildPhaseOverrideSequence` line). Our app plist ≈ hex's hand-written one. The widget plist ≈ KeyVox's (only `NSExtension` → `com.apple.widgetkit-extension`).
- **`NSSupportsLiveActivities`** belongs in the app target only ([doc](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)). That is where it is.
- **Entitlements and assets.** No entitlement file is required for this code. No asset catalog is required either: XcodeGen sets `ASSETCATALOG_COMPILER_APPICON_NAME`, but without an `.xcassets` folder actool never runs. The app just has no icon.
